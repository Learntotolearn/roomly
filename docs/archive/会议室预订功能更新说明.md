# 会议室预订功能更新说明

## 更新内容

本次更新对会议室预订系统进行了以下重要改进：

### 1. 移除机器人单独发送会议通知
- 移除了原有的机器人单独发送会议通知功能
- 改为使用群组通知方式，提供更好的协作体验

### 2. 自动创建群组功能
- 在会议室预订成功后，系统会自动创建群组
- 将所有参会人员自动添加到群组中
- 群组名称格式：`会议群组 - {会议室名称} - {会议时间}`
- 使用 dootask 工具包的 CreateGroup API 创建群组
- 群组创建成功后，会话ID会保存到数据库的 `dialog_id` 字段中

### 3. 群组通知功能
- 在群组中发送会议相关通知
- 使用会议发起人的身份发送通知
- 通知内容包括：会议室、时间、参会人员、预定理由等

### 4. 会议结束通知
- 实现了会议结束后的自动通知功能
- 使用定时任务每分钟检查会议是否过期
- 会议过期时自动发送"会议结束"通知到群组

### 5. 数据库结构更新
- 在 `bookings` 表中添加了 `dialog_id` 字段
- 用于存储群组ID，以便发送会议结束通知

## 技术实现

### 主要文件修改

1. **server/models/sendmessge.go**
   - 添加了 `CreateGroupAndSendNotification` 方法
   - 添加了 `SendMeetingEndNotification` 方法
   - 修改了 `SendMessageWithToken` 方法，对新的会议提醒使用群组通知

2. **server/models/models.go**
   - 在 `Booking` 结构体中添加了 `DialogID` 字段

3. **server/handlers/booking_handler.go**
   - 修改了 `CreateBooking` 方法，使用群组通知替代机器人通知
   - 保存群组ID到数据库

4. **server/handlers/booking_realtime.go**
   - 添加了 `sendMeetingEndNotification` 方法
   - 修改了 `CheckAndUpdateExpiredBookings` 方法，添加会议结束通知

5. **server/main.go**
   - 重新启用了定时任务，每分钟检查会议过期
   - 添加了 `sendMeetingEndNotification` 方法

### API接口

会议结束通知使用以下API接口：
```
GET https://t.hitosea.com/api/dialog/msg/sendnotice?dialog_id={群组ID}&notice={通知内容}&token={用户Token}
```

## 部署说明

### 1. 数据库迁移
运行以下SQL脚本添加新字段：
```sql
ALTER TABLE bookings ADD COLUMN dialog_id INTEGER DEFAULT 0;
UPDATE bookings SET dialog_id = 0 WHERE dialog_id IS NULL;
```

### 2. 配置说明
- 已实现真正的群组创建功能，使用 dootask 工具包的 CreateGroup API
- 群组创建成功后，会话ID会自动保存到数据库
- Token管理：当前使用示例token，实际部署时需要从用户认证系统获取

### 3. 定时任务
- 系统会每分钟检查一次会议是否过期
- 过期的会议会自动发送结束通知
- 可以通过修改 `main.go` 中的 `time.Sleep(1 * time.Minute)` 来调整检查频率

## 注意事项

1. **群组创建**：已实现真正的群组创建功能，使用 dootask 工具包的 CreateGroup API
2. **Token管理**：需要根据实际用户认证系统获取正确的token
