## 🎯 功能概述

Roomly备份还原功能为系统管理员提供完整的数据保护解决方案，支持：

- **手动备份**：按需创建完整数据备份
- **多格式支持**：JSON和SQL两种备份格式
- **安全还原**：带预览确认的数据还原流程
- **完整性验证**：MD5校验确保数据完整性
- **操作审计**：详细的操作日志记录

## 🔐 权限要求

**重要提醒**：备份还原功能仅限系统管理员使用。

- 需要管理员账户登录
- 非管理员用户无法访问相关页面
- 所有API接口都有权限验证

## 🚪 访问入口

### 主要入口
- **备份管理页面**：`/admin/backup`
- **数据还原页面**：`/admin/backup/restore`

### 导航路径
1. 登录管理员账户
2. 进入管理后台
3. 选择"备份管理"菜单项

## 💾 备份管理

### 创建备份

#### 操作步骤
1. 访问备份管理页面
2. 点击"立即备份"按钮
3. 选择备份格式：
   - **JSON格式**：结构化数据，便于查看和编辑
   - **SQL格式**：数据库脚本，便于直接导入
4. 点击"开始备份"
5. 等待备份完成

#### 备份内容
系统会备份以下数据：
- 会议室信息
- 预订记录
- 用户预订历史
- 系统配置信息
- 会议纪要和录音记录

**注意**：会员信息来自DooTask集成，不包含在备份中，但预订记录会保留预订人信息。

### 备份文件管理

#### 文件列表
备份文件列表显示：
- 文件名（包含创建时间）
- 文件大小
- 备份格式（JSON/SQL）
- 创建时间
- MD5校验和
- 操作按钮

#### 可用操作
- **下载**：下载备份文件到本地
- **还原**：使用该备份还原数据
- **验证**：检查文件完整性
- **删除**：删除不需要的备份文件

### 文件命名规则
```
backup_YYYYMMDD_HHMMSS.json
backup_YYYYMMDD_HHMMSS.sql

示例：
backup_20241217_143022.json
backup_20241217_143022.sql
```

## 🔄 数据还原

### 还原前准备

#### 重要提醒
⚠️ **数据还原会覆盖当前所有数据，请谨慎操作！**

#### 建议步骤
1. 在还原前创建当前数据的备份
2. 确认要还原的备份文件是正确的
3. 通知相关用户系统将暂时不可用

### 还原操作流程

#### 1. 选择备份文件
- 访问还原页面或在备份列表中点击"还原"
- 从下拉列表中选择要还原的备份文件
- 系统会显示备份文件的详细信息

#### 2. 预览备份内容
- 点击"预览备份内容"
- 查看备份中包含的数据统计：
  - 会议室数量
  - 预订记录数量
  - 用户数量
  - 其他数据统计

#### 3. 安全选项
- **预还原备份**：勾选此选项会在还原前自动创建当前数据备份
- 建议始终启用此选项作为安全保障

#### 4. 执行还原
1. 确认所有信息无误
2. 点击"开始还原"
3. 在确认对话框中再次确认
4. 等待还原完成
5. 系统会显示还原结果

### 还原后验证
- 检查关键数据是否正确还原
- 验证系统功能是否正常
- 查看操作日志确认还原状态

## 📊 操作日志

### 日志功能
操作日志记录所有备份还原相关的操作，包括：
- 备份创建
- 数据还原
- 文件删除
- 验证操作
- 错误信息

### 日志信息
每条日志包含：
- **操作类型**：backup/restore/delete/validate
- **操作状态**：success/failed/in_progress
- **文件名**：相关的备份文件
- **操作者**：执行操作的管理员
- **执行时间**：操作开始和完成时间
- **耗时**：操作持续时间
- **错误信息**：失败时的详细错误

### 日志管理
- **过滤**：按操作类型、状态、时间范围过滤
- **分页**：支持分页浏览历史记录
- **清理**：删除过期的日志记录
- **导出**：导出日志用于审计

## 🔧 故障排除

### 常见问题

#### 1. 备份创建失败
**可能原因**：
- 磁盘空间不足
- 数据库连接问题
- 权限不足

**解决方案**：
- 检查服务器磁盘空间
- 确认数据库服务正常
- 检查文件系统权限

#### 2. 还原失败
**可能原因**：
- 备份文件损坏
- 格式不兼容
- 数据库锁定

**解决方案**：
- 使用验证功能检查文件完整性
- 确认备份文件格式正确
- 重启数据库服务

#### 3. 文件下载失败
**可能原因**：
- 文件不存在
- 网络问题
- 浏览器限制

**解决方案**：
- 刷新页面重试
- 检查网络连接
- 尝试其他浏览器

### 错误代码说明

| 错误代码 | 说明 | 解决方案 |
|---------|------|----------|
| BACKUP_001 | 创建备份失败 | 检查磁盘空间和权限 |
| BACKUP_002 | 文件写入失败 | 检查文件系统权限 |
| RESTORE_001 | 还原失败 | 检查备份文件完整性 |
| RESTORE_002 | 数据库操作失败 | 检查数据库连接 |
| VALIDATE_001 | 文件验证失败 | 文件可能已损坏 |

### 紧急恢复

如果系统出现严重问题：

1. **立即停止所有操作**
2. **检查最近的备份文件**
3. **使用最新的有效备份进行还原**
4. **联系技术支持**

## ⚙️ 技术规格

### 系统要求
- Go 1.23+
- SQLite 3.x
- 磁盘空间：至少预留数据库大小的3倍空间

### 备份格式规格

#### JSON格式
```json
{
  "metadata": {
    "version": "1.0",
    "created_at": "2024-12-17T14:30:22Z",
    "total_records": 1250
  },
  "data": {
    "rooms": [...],
    "bookings": [...],
    "users": [...]
  }
}
```

#### SQL格式
```sql
-- Roomly Database Backup
-- Created: 2024-12-17 14:30:22
-- Version: 1.0

BEGIN TRANSACTION;

CREATE TABLE IF NOT EXISTS rooms (...);
INSERT INTO rooms VALUES (...);

-- ... 其他表结构和数据

COMMIT;
```

### 性能指标
- **小型数据库**（<100MB）：备份时间 < 30秒
- **中型数据库**（100MB-1GB）：备份时间 < 5分钟
- **大型数据库**（>1GB）：备份时间视数据量而定

### 安全特性
- **权限验证**：所有操作都需要管理员权限
- **路径安全**：防止路径遍历攻击
- **事务保护**：还原操作使用数据库事务
- **完整性校验**：MD5校验确保文件完整性
